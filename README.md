# PlateletPlan

**Forecasting and rebalancing short-life platelet stock across a district's blood centres.**

Platelets last only 5 days. Published audits of Indian government and teaching-hospital blood banks report that **45–61% of platelets are discarded**, almost all because they expire. The same centres still run short during dengue season. PlateletPlan is an open-source planning assistant for a blood centre's medical officer. Every morning it:

1. **forecasts** platelet demand for the next 3 days (LASSO regression on recent usage, day of week and the district dengue signal),
2. **recommends how many platelet units to prepare** from today's donations,
3. **flags near-expiry units** and the nearby centre most likely to use them (minimum-cost flow with OR-Tools),
4. **explains** each number in one line, e.g. *"Monday +1.3; dengue cases 45/week (+18% vs 4 weeks ago) +1.2"*.

> **Data honesty:** no public dataset of daily platelet demand at Indian blood centres exists. The centre-level data in this repository is **synthetic**, generated by a seeded, documented script ([docs/DATA.md](docs/DATA.md)). It is calibrated to published discard rates and real NCVBDC dengue figures. The results below show that **the method works**. They are **not** a measured real-world saving.

---

## Input → Output

| | |
|---|---|
| **Input** | A centre's daily history of platelet units issued; today's stock with days of life left; today's donations; district dengue cases (reported with a one-week lag) |
| **Output** | Forecast for today and the next 2 days; number of units to prepare today; units to send to or receive from nearby centres; a one-line reason |

```
$ python -m plateletplan.cli plan --centre A --date 2025-10-06
PlateletPlan · Centre A - Medical college · 2025-10-06

PREPARE TODAY: 11 platelet units (from 28 donations)
Why: Monday +1.3; dengue cases 45/week (+18% vs 4 weeks ago) +1.2
Forecast demand: 2025-10-06: 17.2, 2025-10-07: 16.5, 2025-10-08: 15.7
Stock this morning: 47 units (4 day(s) left: 14, 3 day(s) left: 14, 2 day(s) left: 14, 1 day(s) left: 5)
District dengue cases reported last week: 45
```

## Quick start

Requires Python 3.10+.

```bash
git clone <this repo> && cd plateletplan
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python -m plateletplan.cli generate                    # write synthetic data to data/ (optional, ~2 s)
python -m plateletplan.pipeline                        # full evaluation -> results/ (~1 min)
python -m plateletplan.cli plan --centre A --date 2025-10-06
streamlit run app.py                                   # web app on http://localhost:8501
python -m pytest -q                                    # 6 tests
```

Other commands:

```bash
# Unseen outbreak: 2025 season twice as large and 3 weeks early (models trained before it)
python -m plateletplan.pipeline --out results/stress_test --outbreak-scale 2 --peak-shift-weeks 3 --shock-from-year 2025
python -m plateletplan.cli plan --centre C --date 2025-10-08 --scenario outbreak

# Your own data: one centre's register with columns date, issued [, dengue_cases]
python -m plateletplan.cli register data/sample_register.csv

# Robustness: other random seeds, then combine
python -m plateletplan.pipeline --seed 21 --out results/seeds/seed_21
python -m plateletplan.pipeline --seed 42 --out results/seeds/seed_42
python scripts/summarise_seeds.py
```

## Results (synthetic district of 5 centres, test year 2025)

Time split, never random: forecasting models are fitted on 2021–2023, policy settings are tuned on 2024, and **2025 is untouched until the final test**. Every policy is tuned the same way, minimising *expired units + 10 × short units* (assumption: a shortage is ten times worse than a wasted unit).

**Seed 7 (main run):**

| Policy | Units prepared | Expired | Expiry rate | Short | Shortage rate | Transferred |
|---|---:|---:|---:|---:|---:|---:|
| Status quo (platelets from every donation) | 17,848 | 8,485 | 47.5% | 0 | 0.00% | 0 |
| 7-day average baseline | 9,798 | 401 | 4.1% | 22 | 0.23% | 0 |
| PlateletPlan (LASSO forecast) | 9,690 | 290 | 3.0% | 17 | 0.18% | 0 |
| **PlateletPlan + transfers** | 9,751 | 344 | 3.5% | **13** | **0.14%** | 129 |

**Mean of 3 seeds (7, 21, 42)** (`results/summary_across_seeds.csv`):

| Policy | Expiry rate (range) | Shortage rate | Expired + 10 × short |
|---|---:|---:|---:|
| Status quo | 48.7% (47.5–50.0) | 0.00% | 8,672 |
| 7-day average baseline | 5.3% (4.1–7.6) | 0.20% | 692 |
| PlateletPlan (LASSO) | 2.8% (2.0–3.6) | 0.22% | 468 |
| **PlateletPlan + transfers** | 3.4% (3.0–3.6) | **0.13%** | **442** |

What this shows, and what it does not:

- **Most of the gain comes from planning at all.** Any forecast-based rule, even a 7-day average, removes most of the status quo's waste. In the status quo, centres make platelets from every donation; that assumption is calibrated to the 45% published discard rate.
- **The forecasting model beats the simple baseline.** Its weighted cost is 32% lower, and its forecast error (WAPE) is 0.51 against 0.54 for the baseline. Daily demand at small centres is very noisy, so no model gets close to perfect.
- **Transfers mainly reduce shortages.** On average across seeds they give 30% fewer short units than the baseline (12 vs 18), at about the same expiry rate. The effect varies by seed.

**Unseen-outbreak stress test** (`results/stress_test/`; 2025 dengue season 2× larger and 3 weeks early, never seen in training):

| Policy | Expiry rate | Short units | Shortage rate |
|---|---:|---:|---:|
| Status quo | 41.7% | 22 | 0.21% |
| 7-day average baseline | 3.7% | 107 | 1.02% |
| PlateletPlan (LASSO) | 3.6% | 80 | 0.76% |
| PlateletPlan + transfers | 4.2% | 56 | 0.53% |

Honest reading: in a surprise outbreak, shortages rise for every forecast-based policy. The status quo's huge overstock protects it slightly better (22 short units), at the cost of about 7,000 more expired units. Transfers halve shortages compared with the baseline. An "outbreak mode" that raises the safety stock when dengue cases climb fast is the top open issue.

## How it works

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). In short:

```
dengue signal + usage history ──> LASSO forecast (h = 0,1,2) ──> order-up-to rule ──> prepare N units
                                         │                                ▲
                                         └──> near-expiry surplus / deficit ──> OR-Tools min-cost flow ──> transfers
                                         └──> feature contributions ──> one-line reason
```

## Limitations

- **Synthetic demand.** The size of the gain at a real centre is unproven until a centre's anonymised register is tested. The `register` command and app tab exist for exactly that.
- **The status quo is an assumption.** It is modelled as "make platelets from every donation", calibrated to the published 45% discard rate. Real practice varies and should be confirmed with blood centre staff.
- **No blood groups.** ABO/Rh matching is not modelled. Real shortages are partly group-specific, so real shortage rates will be higher than simulated.
- **Clinical appropriateness is out of scope.** The tool forecasts the demand that arrives, including any unnecessary prophylactic transfusions.
- **Transfers are idealised.** Same-day transport within 90 minutes is assumed, with no licensing paperwork, transport cost or cold-chain failure. Travel times are straight-line distance × 1.35 at 40 km/h, not OpenStreetMap routing.
- **The shortage weight (10×) is a value judgement.** Change `SHORTAGE_WEIGHT` in `pipeline.py` to see the trade-off; the tuning grids in `results/` show the whole frontier.
- **The register back-test is optimistic.** The register feature tunes and tests on the same last 30% of days, so treat its back-test as indicative.
